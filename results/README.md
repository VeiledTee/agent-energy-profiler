# Diagnostic results

Raw data behind [docs/NVML_COUNTER_VALIDATION.md](../docs/NVML_COUNTER_VALIDATION.md)
(Milestone 4) and the sampler checks in
[docs/MEASUREMENT_MODES.md](../docs/MEASUREMENT_MODES.md) (Milestone 5). They
are kept so that the published findings can be re-analysed and checked. They
are not part of the package and are not in the source distribution.

**One configuration only.** Every file comes from a single machine: NVIDIA
GeForce RTX 4090, driver 610.88, under WSL2 (kernel
5.15.167.4-microsoft-standard-WSL2), AMD Ryzen 7 7800X3D, Python 3.12. No
file here measures accuracy, because no external power meter was used. The
counter-disturbance finding has not been repeated on another GPU, driver or
operating system.

## Files

| Path | Produced by | Contents |
|---|---|---|
| `nvml_m4/{idle,steady,pulsed}/meta.json` | `tools/nvml_diagnostics/experiment.py` | arguments, seed, condition list, GPU and host description of each experiment |
| `nvml_m4/{idle,steady,pulsed}/trials.jsonl` | the same | one record per trial: endpoint counter reads, every in-window NVML read with its timing (raw data, 3.4 MB) |
| `nvml_m4/summary.json`, `summary.md`, `retained_vs_read_rate.png` | `tools/nvml_diagnostics/analyze.py` | per-condition statistics and the figure used in the validation document |
| `nvml_m4/step_response.json` | `tools/nvml_diagnostics/step_response.py` | counter and power response to a load step |
| `nvml_m4/aep_validate_counter_disturbance.json`, `nvml_m5/aep_validate_counter_disturbance.json` | `agent-energy-profiler validate --counter-disturbance --json` (named `aep validate` when recorded) | the built-in quick check: verdict, retained ratios, hardware report |
| `nvml_m5/sampler_interference.json` | `tools/nvml_diagnostics/sampler_interference.py` | effect of the real sampler process on other counter readers |

## Reproducing the analysis

The summaries are regenerated byte-for-byte from the raw trials:

```bash
python tools/nvml_diagnostics/analyze.py results/nvml_m4/idle \
    results/nvml_m4/steady results/nvml_m4/pulsed --out /tmp/m4-check
cmp /tmp/m4-check/summary.json results/nvml_m4/summary.json
```

Re-running the experiments themselves needs an NVIDIA GPU, the `[gpu]` extra,
and for the loaded workloads an interpreter with PyTorch and CUDA
(`tools/nvml_diagnostics/README.md`). Results from another machine are new
data, not a reproduction of these values.

## Redactions before publication

- `pynvml_module` held the absolute path of the developer's virtual
  environment; it now starts at `.venv/` (the rest of the path is unchanged).
- The host name in both hardware reports is `redacted-host`, as in the golden
  fixtures. The `auto` mode therefore never treats these reports as
  describing the machine it runs on (both verdicts are `DISTURBED` anyway).
- The experiments' console logs (`*.log`, progress lines duplicated in
  `trials.jsonl`) were removed.

The analysis above reproduces the summaries identically before and after
these redactions. Earlier commits still contain the unredacted values (see
`docs/RELEASING.md`).
